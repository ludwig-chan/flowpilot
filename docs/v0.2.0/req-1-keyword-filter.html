需求 1：搜索与筛选

在数据记录页面提供搜索和筛选功能，帮助用户从大量采集数据中快速定位目标记录。

需求 1

做什么

在数据记录页面提供快速搜索和高级筛选两层能力，帮助用户从大量采集数据中快速定位目标记录。工具栏保持简洁，复杂操作收纳到下拉面板和菜单中。
详细要求
  • 搜索范围：搜索文本 = 所有字段值 + 关联截图的 OCR 文本
  • 快速搜索 简版
    • 工具栏搜索框，输入即生效（即时搜索）
    • 在所有字段值和 OCR 文本中模糊匹配
    • 相当于"快速搜一下"，简单直接
  • 高级筛选 精确
    • 支持多组条件，每组可独立设置匹配逻辑（AND / OR）
    • 白名单（包含）：多组条件，组内可设置 AND（都要有）或 OR（有一个就行），组间为 AND 关系（所有组都要满足）
    • 黑名单（排除）：多组条件，组内可设置 AND 或 OR，组间为 OR 关系（任一组命中就排除）
    • 时间范围筛选（精确到分钟），快捷选项（今天、最近 7 天、最近 30 天、自定义）
  • 搜索与筛选的关系
    • 快速搜索和高级筛选同时生效，取交集
    • 例：搜索框输入"React"，高级筛选排除"外包"，结果 = 包含 React 且不包含外包
  • 筛选预设 新功能
    • 用户可将高级筛选的条件保存为预设（起个名字）
    • 下次从预设下拉框选择，一键恢复整套筛选条件
    • 预设支持编辑、删除
    • 预设存储在 data-record-library.json 中

使用示例

通过多组条件组合，可以表达复杂的筛选需求：

示例 1：筛选前端工程师简历
白名单第 1 组（AND）：React、Vue、TypeScript → 必须都有
白名单第 2 组（OR）：App、小程序 → 有一个就行
组间 AND：两组都要满足
最终：记录必须同时包含 React+Vue+TS，且包含 App 或小程序
示例 2：排除不想要的记录
黑名单第 1 组（OR）：外包、实习 → 有一个就排除
黑名单第 2 组（AND）：女性、25岁 → 两个都有才排除
组间 OR：任一组命中就排除
最终：包含"外包"或"实习"就排除，或者同时包含"女性+25岁"也排除
预设管理

预设 = 筛选条件的快捷方式。用户在高级筛选面板中配好条件后，可以保存为预设，下次一键加载。

保存预设
  • 在高级筛选面板中配好条件
  • 点击"保存为预设"
  • 弹出输入框填写预设名称
  • 保存后出现在预设下拉列表中
管理预设
  • 加载：从下拉列表选择，条件自动填入面板
  • 编辑：修改条件后重新保存（覆盖原预设）
  • 删除：从预设列表中移除
存储位置：预设数据存储在 data-record-library.json 中，新增 filterPresets 字段。
注意事项
  • OCR 文本时序
    • OCR 文字是页面加载后逐步识别的
    • 尚未识别的截图无法被搜索到
    • 可在工具栏提示"X 张截图待 OCR 识别"
  • 性能
    • 快速搜索为即时搜索，使用 useMemo 缓存计算结果
    • 数据量大时（>5000 条）可考虑对搜索文本做预计算
  • 与需求 2（批量标记）的衔接
    • "更多"菜单中的"打标签"功能属于需求 2
    • 筛选结果直接作为批量操作的选中范围
    • 两个需求共享工具栏，但逻辑可独立开发
